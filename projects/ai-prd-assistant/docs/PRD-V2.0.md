## 1. 核心修改原则

### 1.1 从“文档生成工具”升级为“产品经理工作流Agent”

旧定位：

> AI帮助产品经理生成PRD。

新定位：

> AI Agent辅助产品经理完成从需求发现、需求分析、产品设计到PRD评审的完整工作流。

### 1.2 产品关系变化

| 维度 | 旧版本 | V2.0 |
| --- | --- | --- |
| AI角色 | 文档生成器 | 产品经理的智能协作伙伴 |
| 工作起点 | 输入需求文本 | 输入用户访谈、会议纪要、竞品资料、用户反馈 |
| 工作终点 | 输出PRD | 输出洞察、需求、方案、PRD和质量评审 |
| 决策参与 | 少 | 参与需求优先级和方案设计 |
| 质量保障 | 无 | Review Agent模拟产品负责人评审 |

### 1.3 设计原则

1. AI不是替代产品经理写文档。
2. AI是产品经理的智能协作伙伴。
3. 每个Agent都有明确输入、处理逻辑和输出结果。
4. 人工在环：AI生成初稿，产品经理负责判断和决策。
5. 结果可解释：PRD评审必须输出问题、建议和质量评分。

## 2. 产品定位

### 2.1 一句话定位

PRD Copilot是面向产品团队的AI需求分析与产品设计Agent，通过理解用户声音、业务目标和产品规范，自动完成需求洞察、方案设计、PRD生成和质量评审。

### 2.2 核心价值

1. 需求洞察：从访谈、反馈和竞品资料中发现用户问题和机会。
2. 需求分析：将信息转化为用户故事和P0/P1/P2需求。
3. 产品设计：辅助生成功能模块、用户流程和页面结构。
4. PRD生成：输出标准、完整、可评审的PRD。
5. 质量评审：模拟产品负责人视角检查需求完整性和边界情况。

### 2.3 产品定位关键词

- AI Native
- Agent Workflow
- 产品设计
- 团队协作
- 人工在环

## 3. 产品背景

### 3.1 行业背景

产品经理的核心工作不是写文档，而是把模糊的业务问题转化为清晰、可执行的产品方案。

但实际工作中，产品经理大量时间被以下工作占用：

- 整理访谈记录
- 归纳用户反馈
- 梳理需求池
- 调整PRD结构
- 应对评审修改

这些工作重复性高、信息分散、依赖个人经验。

### 3.2 当前产品经理工作流程

```text
用户访谈
  ↓
会议记录
  ↓
需求整理
  ↓
用户画像
  ↓
需求分析
  ↓
功能设计
  ↓
PRD撰写
  ↓
评审修改
```

### 3.3 当前问题

| 问题 | 影响 |
| --- | --- |
| 信息碎片化 | 访谈、会议、竞品资料分散，需求容易遗漏 |
| 重复整理成本高 | 同一份信息被反复整理、排版、改写 |
| 新人经验不足 | 缺少标准流程和模板，产出质量不稳定 |
| PRD质量依赖个人能力 | 需求完整性、边界情况和验收标准因人而异 |

### 3.4 LLM为什么适合解决该问题

LLM具备四类能力，正好匹配产品经理工作流：

1. 长文本理解：理解访谈记录、会议纪要和用户反馈。
2. 信息提取：从非结构化内容中提取用户问题、需求和场景。
3. 结构化生成：输出用户画像、需求清单、功能模块和PRD结构。
4. 逻辑检查：检查需求是否明确、功能是否合理、是否缺少边界情况。

## 4. 用户画像

### 4.1 用户1：产品经理

| 维度 | 内容 |
| --- | --- |
| 角色 | 产品经理 |
| 工作场景 | 负责新产品需求分析，需要从访谈和反馈中提炼需求 |
| 当前任务 | 整理需求素材、分析用户问题、设计功能、撰写PRD |
| 痛点 | 信息整理耗时，需求容易遗漏，PRD修改频繁 |
| 使用AI后 | AI自动完成洞察、需求拆解和PRD初稿，产品经理集中做判断 |

**真实业务案例：**

产品经理收到50份用户访谈记录，需要整理成需求池。使用PRD Copilot后，AI自动提取用户问题、场景和机会点，并生成P0/P1/P2需求清单，产品经理只需确认和补充。

### 4.2 用户2：产品负责人

| 维度 | 内容 |
| --- | --- |
| 角色 | 产品负责人 |
| 工作场景 | 需要快速评审多个需求方案 |
| 当前任务 | 判断需求是否清晰、功能是否合理、范围是否可控 |
| 痛点 | 不同PRD结构不一致，评审效率低；边界情况常被遗漏 |
| 使用AI后 | Review Agent模拟评审视角，提前输出问题、建议和质量评分 |

**真实业务案例：**

产品负责人需要在一周内评审多个需求方案。使用PRD Copilot后，每个方案自动生成PRD质量评分、问题列表和修改建议，负责人可以快速聚焦高风险需求。

### 4.3 用户3：产品新人/实习生

| 维度 | 内容 |
| --- | --- |
| 角色 | 产品新人/实习生 |
| 工作场景 | 学习产品设计流程，完成第一个PRD |
| 当前任务 | 模仿模板撰写PRD，理解需求分析和功能设计 |
| 痛点 | 缺少标准流程，不知道PRD应该包含什么，容易漏验收标准 |
| 使用AI后 | AI提供结构化工作流和示例，帮助新人快速学习产品设计方法 |

**真实业务案例：**

产品实习生需要为内容管理平台撰写第一份PRD。使用PRD Copilot后，AI生成标准PRD结构和验收标准示例，实习生可以基于初稿学习和修改。

## 5. 用户使用流程（User Journey）

### 5.1 完整流程

```text
Step 1 输入需求素材
  ↓
Step 2 Research Agent分析
  ↓
Step 3 Requirement Agent
  ↓
Step 4 Product Design Agent
  ↓
Step 5 PRD Writer Agent
  ↓
Step 6 Review Agent
```

### 5.2 流程拆解

| Step | 用户行为 | Agent处理 | 用户获得 | 决策价值 |
| --- | --- | --- | --- | --- |
| 1 输入需求素材 | 输入访谈、会议纪要、竞品资料、用户反馈 | 数据整理与信息识别 | 统一的需求素材 | 减少人工整理 |
| 2 Research Agent分析 | 等待分析 | 理解资料，提取用户问题与机会 | 用户洞察 | 知道用户要什么 |
| 3 Requirement Agent | 查看需求清单 | 生成用户故事和优先级 | P0/P1/P2需求 | 知道先做什么 |
| 4 Product Design Agent | 查看方案 | 生成功能模块、流程、页面结构 | 产品方案 | 知道怎么做 |
| 5 PRD Writer Agent | 查看PRD | 生成标准PRD | 完整PRD初稿 | 可以直接评审 |
| 6 Review Agent | 查看评审结果 | 模拟负责人评审 | 问题、建议、质量评分 | 知道哪里要改 |

## 6. AI Agent架构

### 6.1 架构总览

```text
Research Agent
  ↓
Requirement Analyst Agent
  ↓
Product Designer Agent
  ↓
PRD Writer Agent
  ↓
Review Agent
```

### 6.2 Agent 1：Research Agent

**职责：**

理解输入资料，提炼用户洞察。

**输入：**

- 用户访谈
- 会议纪要
- 竞品资料
- 用户反馈

**处理逻辑：**

1. 识别用户问题。
2. 提取使用场景。
3. 发现需求机会。
4. 输出关键洞察。

**输出：**

- 用户问题
- 需求机会
- 关键洞察

### 6.3 Agent 2：Requirement Analyst Agent

**职责：**

将洞察转化为用户故事和需求列表。

**输入：**

- Research Agent输出的用户洞察

**处理逻辑：**

1. 将用户问题转化为用户故事。
2. 评估用户价值和业务价值。
3. 输出P0/P1/P2优先级。

**输出：**

- 用户故事
- 需求列表
- 优先级

示例用户故事：

> 作为运营人员，我希望快速分析用户反馈，从而发现增长机会。

### 6.4 Agent 3：Product Designer Agent

**职责：**

辅助产品方案设计。

**输入：**

- 需求清单
- 用户故事

**处理逻辑：**

1. 拆解功能模块。
2. 设计用户流程。
3. 建议页面结构。
4. 定义业务规则。

**输出：**

- 功能模块
- 用户流程
- 页面结构

### 6.5 Agent 4：PRD Writer Agent

**职责：**

生成标准PRD。

**输入：**

- 用户画像
- 需求清单
- 功能方案

**处理逻辑：**

1. 组织PRD结构。
2. 补充功能说明。
3. 生成验收标准。

**输出：**

- 背景
- 目标
- 用户
- 功能
- 流程
- 验收标准

### 6.6 Agent 5：Review Agent

**职责：**

模拟产品负责人评审。

**输入：**

- PRD Writer Agent生成的PRD

**处理逻辑：**

1. 检查需求是否明确。
2. 检查功能是否合理。
3. 检查是否缺少边界情况。
4. 输出质量评分。

**输出：**

- PRD质量评分
- 问题列表
- 修改建议

## 7. 功能模块设计

### F1 多源需求输入

**功能说明：**

支持文本、访谈记录、会议纪要、竞品分析等需求素材输入。

**用户价值：**

减少人工整理，统一需求信息来源。

**输出：**

- 结构化需求素材
- 信息类型标签

### F2 AI需求洞察

**功能说明：**

由Research Agent分析需求素材，输出用户问题、场景和机会点。

**用户价值：**

产品经理快速获得用户洞察，不需要逐份阅读访谈。

**输出：**

- 用户问题
- 场景
- 机会点

### F3 用户画像生成

**功能说明：**

生成用户角色卡，包括目标、行为和痛点。

**用户价值：**

帮助产品团队统一对目标用户的理解。

**输出：**

- 用户角色卡
- 目标
- 行为
- 痛点

### F4 AI需求池管理

**功能说明：**

生成需求列表，并管理优先级。

**用户价值：**

产品经理获得可维护的需求池，而不是零散笔记。

**字段：**

- 需求描述
- 用户价值
- 业务价值
- 优先级

### F5 功能方案设计

**功能说明：**

由Product Designer Agent生成功能模块、页面流程和业务规则。

**用户价值：**

产品经理可以快速评估产品方案，而不是从零设计。

**输出：**

- 功能模块
- 页面流程
- 业务规则

### F6 PRD自动生成

**功能说明：**

由PRD Writer Agent生成标准PRD结构。

**用户价值：**

PRD初稿可评审、可修改，减少重复撰写。

**输出：**

- 标准PRD
- 功能说明
- 验收标准

### F7 AI PRD Review

**功能说明：**

由Review Agent检查PRD质量和完整性。

**用户价值：**

在正式评审前提前发现问题，降低返工成本。

**输出：**

- 问题列表
- 修改建议
- 质量评分

## 9. MVP设计

### 9.1 MVP目标

验证核心假设：

> AI是否能够降低产品经理需求分析和PRD撰写成本。

### 9.2 MVP必须包含

1. 需求素材输入
2. 用户画像生成
3. 需求拆解
4. 功能设计
5. PRD生成
6. AI Review

### 9.3 MVP暂不包含

- 实时协作
- 企业知识库
- 复杂权限系统

### 9.4 MVP成功标准

| 指标 | 目标 |
| --- | --- |
| PRD初稿生成时间 | 30秒内 |
| 需求完整率 | 不低于85% |
| 用户修改时间 | 降低50% |
| AI Review覆盖度 | 覆盖全部生成PRD |

> 以上为模拟目标值，非真实商业数据。

## 10. 产品指标体系

### 10.1 North Star Metric

**有效PRD产出效率**

定义：单位时间内产出并达到评审标准的PRD数量。

### 10.2 效率指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| PRD初稿生成时间 | 从输入素材到PRD初稿的时间 | 30秒内 |
| 需求整理时间 | 从访谈记录到需求池的时间 | 降低60% |

### 10.3 质量指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| PRD完整度评分 | Review Agent对PRD结构的评分 | 不低于85分 |
| 需求遗漏率 | 用户确认后补充的需求比例 | 不高于15% |
| 验收标准覆盖度 | 核心功能具有验收标准的比例 | 不低于90% |

### 10.4 体验指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 用户满意度 | 产品经理对PRD初稿满意度 | 4分以上（5分制） |
| 持续使用意愿 | 是否愿意纳入正式工作流 | 不低于70% |

### 10.5 业务指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 需求评审通过率 | PRD一次评审通过比例 | 提升30% |
| PRD返工次数 | 评审后大幅修改次数 | 降低50% |

> 所有指标均为模拟验证指标，非真实商业数据。

## 11. Portfolio Story

### 11.1 产品背景

产品经理大量时间消耗在信息整理和PRD撰写上，真正用于需求判断的时间不足。

### 11.2 用户痛点

信息碎片化、重复整理成本高、新人经验不足、PRD质量依赖个人能力。

### 11.3 AI机会

LLM具备长文本理解、信息提取、结构化生成和逻辑检查能力，适合辅助产品经理工作流。

### 11.4 Agent设计

五个Agent分别负责研究、需求、设计、写作和评审，形成完整的产品经理工作流。

### 11.5 产品方案

F1至F7覆盖需求输入、洞察、画像、需求池、功能设计、PRD生成和AI Review。

### 11.6 MVP验证

验证AI能否降低需求分析和PRD撰写成本，并通过效率、质量、体验、业务四类指标衡量。

### 11.7 未来规划

- 实时协作
- 企业知识库
- 团队模板
- 与Jira、Notion等工具打通

## 12. 现有UI一致性检查与页面修改建议

### 12.1 检查结论

现有原型保留了完整功能页面，但UI仍偏向“PRD文档生成工具”，与V2.0“AI Product Manager Agent”定位不完全一致。

### 12.2 需要修改的页面

| 页面 | 现状 | 需要修改 |
| --- | --- | --- |
| 文档工作台 | 左侧大纲、中间文档、右侧配置 | 增加Research Agent“需求洞察”阶段 |
| PRD文档画布 | 用户画像、需求清单、功能模块、大纲、验收标准、风险 | 增加AI Review质量评分和问题列表 |
| 需求清单 | 只有需求标题和用户故事 | 增加用户价值、业务价值、优先级字段 |
| 功能模块 | 只有模块名称和描述 | 增加页面流程和业务规则 |
| 产品官网 | 六步流程较通用 | 改为五个Agent工作流 |
| 项目PDF | 当前为17页方案PDF | 按V2.0结构重新组织 |

### 12.3 修改原则

1. 不删除已有功能页面。
2. 在现有页面上增加Agent阶段和评审模块。
3. 保持PRD Copilot名称和核心功能方向不变。
